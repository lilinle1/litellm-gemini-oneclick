# LiteLLM Gemini Proxy · One-Click Deploy (GCP Cloud Run · Keyless)

English | [简体中文](./README_CN.md)

One-click deployment of a [LiteLLM](https://github.com/BerriAI/Litellm) proxy on GCP Cloud Run that translates requests from any client (Cherry Studio, CC Switch, Claude Code, etc.) to Vertex AI Gemini models.

**Key advantage: fully keyless** — no service-account key files are ever exported, avoiding account risk. Billing goes through Vertex AI and draws down the **$300 free trial credit** for new GCP users first.

## Features

- Single command handles everything: API enablement, service account, IAM bindings, Secret Manager, and Cloud Run deployment
- Keyless architecture: Cloud Run talks to Vertex AI via its attached service account — zero key files on your machine
- OpenAI & Claude compatible: `/v1` OpenAI-style endpoint, plus built-in Claude aliases (e.g. `claude-sonnet-4-6`) that route to Gemini
- `drop_params` silently ignores non-standard client params to prevent 400 errors
- Config lives in Secret Manager — edit `config.yaml` and re-run the script to hot-update the model list
- API key is randomly generated by default and can be looked up anytime via the management menu
- Interactive management menu: view info / hot update / full uninstall / selective uninstall

## Prerequisites

- A GCP account (new users get the [$300 free trial credit](https://cloud.google.com/free))
- [Google Cloud Shell](https://shell.cloud.google.com) (recommended, zero setup), or a local [gcloud CLI](https://cloud.google.com/sdk/docs/install) installation

## Quick Start

```bash
git clone https://github.com/lilinle1/litellm-gemini-oneclick.git
cd litellm-gemini-oneclick
bash deploy.sh
```

Or run directly without cloning:

```bash
curl -fsSL https://raw.githubusercontent.com/lilinle1/litellm-gemini-oneclick/main/deploy.sh | bash
```

When finished, the script prints your service URL and API key:

```
==============================================
  Deployed successfully!
==============================================
  Service URL:  https://litellm-gemini-xxxx.us-central1.run.app
  API endpoint: https://litellm-gemini-xxxx.us-central1.run.app/v1
  API Key:      sk-a3f8...(randomly generated — save it!)
```

### Options

| Flag | Env var | Default | Description |
|---|---|---|---|
| `--region` | `REGION` | `us-central1` | Cloud Run region |
| `--project` | `PROJECT_ID` | current gcloud project | GCP project ID |
| `--service` | `SERVICE_NAME` | `litellm-gemini` | Service name |
| `--key` | `MASTER_KEY` | random | Custom API key |
| `--memory` | `MEMORY` | `2048M` | Container memory (lower values risk OOM) |
| `--cpu` | `CPU` | `2` | Container CPU |

Example:

```bash
bash deploy.sh --region=asia-east1 --key=sk-my-key
```

## Client Configuration

| Client | Configuration |
|---|---|
| **Cherry Studio** | Provider type: OpenAI-compatible; API base: `https://<service-url>/v1`; API key: the generated key; models: `gemini-3.8-flash` / `gemini-3.7-flash` / `gemini-2.5-pro`, etc. |
| **CC Switch / Claude clients** | Endpoint: `https://<service-url>/v1` (no trailing slash); **upstream format must be OpenAI Chat Completions**; keep the client's default model names (e.g. `claude-opus-5-5`, `claude-sonnet-5-5` are auto-redirected to the equivalent Gemini tier). ## Updating the Model List

1. Edit the local `config.yaml` (generated in the working directory by the deploy script) and add model entries following the existing format;
2. Re-run `bash deploy.sh` (or menu option 2) — the config is pushed to Secret Manager and the service is redeployed automatically.

## FAQ

- **Why 2048M memory?** LiteLLM tends to OOM on smaller allocations; the default is a safe value.
- **Why the `global` region?** The latest Gemini model series on Vertex AI must be called via the `global` location.
- **400 error `maxOutputTokens value of 128000 but the supported range is 1 to 65537`?** Claude Opus/Sonnet 5.x clients request a 128K max output by default, but all Gemini models cap output at 65,536 tokens. Cap the max output on the client side: for Claude Code set the env var `CLAUDE_CODE_MAX_OUTPUT_TOKENS=65536` (on Windows: `setx CLAUDE_CODE_MAX_OUTPUT_TOKENS 65536`, then restart the terminal); in Cherry Studio lower the max-output model parameter below 65536.
- **Is `--allow-unauthenticated` safe?** The endpoint accepts anonymous requests, but every call must present the randomly generated `master_key`. Just don't leak the key.
- **How is this billed?** All inference goes through Vertex AI and draws down the $300 free trial credit first; Cloud Run itself has a generous free tier.
